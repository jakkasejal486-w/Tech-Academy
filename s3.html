SQL Lesson 3: Constraints, Keys and Relationships

1. Introduction to SQL Constraints

SQL constraints are rules applied to columns in a database table.

They are used to control the type of data that can be stored in a table and help maintain accurate and reliable data.

For example, a student ID should be unique, an email should not be empty and a student must belong to an existing course.

2. Types of SQL Constraints

Constraint Purpose
PRIMARY KEY Uniquely identifies each record.
FOREIGN KEY Connects two tables.
NOT NULL Prevents empty NULL values.
UNIQUE Ensures values are not duplicated.
DEFAULT Provides a default value.
CHECK Restricts values according to a condition.

3. NOT NULL Constraint

The NOT NULL constraint prevents a column from containing NULL values.

Example

CREATE TABLE students(
id INT,
name VARCHAR(100) NOT NULL,
email VARCHAR(100) NOT NULL
);

In this example, every student must have a name and email.

4. UNIQUE Constraint

The UNIQUE constraint ensures that all values in a column are different.

This is useful for information such as email addresses.

Example

CREATE TABLE students(
id INT,
name VARCHAR(100),
email VARCHAR(100) UNIQUE
);

Two students cannot have the same email address in this column.

5. DEFAULT Constraint

The DEFAULT constraint provides a value automatically when no value is supplied.

Example

CREATE TABLE students(
id INT,
name VARCHAR(100),
status VARCHAR(20) DEFAULT 'Active'
);

If status is not provided, the database can use Active as the default value.

6. CHECK Constraint

The CHECK constraint is used to restrict values according to a condition.

Example

CREATE TABLE students(
id INT,
name VARCHAR(100),
age INT CHECK(age>=18)
);

This example restricts the age according to the specified condition.

7. PRIMARY KEY

A primary key is a column or combination of columns that uniquely identifies each record in a table.

A primary key must contain unique values and cannot contain NULL values.

Example

CREATE TABLE students(
student_id INT PRIMARY KEY,
name VARCHAR(100),
email VARCHAR(100)
);

8. Why is PRIMARY KEY Important?

  • It uniquely identifies each record.
  • It prevents duplicate identification values.
  • It cannot contain NULL values.
  • It helps establish relationships between tables.
  • It makes it easier to identify a particular student or record.

9. Example of Primary Key

student_id name email
1 Sejal sejal@example.com
2 Rahul rahul@example.com
3 Priya priya@example.com

Here, student_id can uniquely identify every student.

10. AUTO_INCREMENT

AUTO_INCREMENT automatically generates a new numeric value when a new record is inserted.

Example

CREATE TABLE students(
student_id INT PRIMARY KEY AUTO_INCREMENT,
name VARCHAR(100),
email VARCHAR(100)
);

When a new student is inserted, the student ID can be generated automatically.

11. Inserting Data with AUTO_INCREMENT

INSERT INTO students(name,email)
VALUES('Sejal','sejal@example.com');

INSERT INTO students(name,email)
VALUES('Rahul','rahul@example.com');

The database automatically generates the student IDs.

12. FOREIGN KEY

A foreign key is a column that creates a relationship between two tables.

It usually refers to the primary key of another table.

Example

CREATE TABLE courses(
course_id INT PRIMARY KEY,
course_name VARCHAR(100)
);

CREATE TABLE students(
student_id INT PRIMARY KEY,
name VARCHAR(100),
course_id INT,
FOREIGN KEY(course_id)
REFERENCES courses(course_id)
);

13. Why is FOREIGN KEY Important?

  • It connects related tables.
  • It helps maintain data consistency.
  • It prevents invalid relationships.
  • It represents relationships between database records.

14. Example of Foreign Key

Suppose the courses table contains:

course_id course_name
1 HTML
2 CSS
3 SQL

The students table can store the corresponding course ID.

student_id name course_id
101 Sejal 1
102 Rahul 2
103 Priya 3

15. Primary Key vs Foreign Key

PRIMARY KEY FOREIGN KEY
Uniquely identifies records. Connects records between tables.
Cannot contain NULL. Can contain NULL unless restricted.
Usually one primary key definition per table. A table can have multiple foreign keys.
Identifies the record in its own table. References a key in another table.

16. Composite Primary Key

A composite primary key consists of two or more columns used together to uniquely identify a record.

Example

CREATE TABLE enrollments(
student_id INT,
course_id INT,
enrollment_date DATE,
PRIMARY KEY(student_id,course_id)
);

Here, the combination of student_id and course_id identifies an enrollment.

17. Database Relationships

Relationships describe how tables are connected to each other.

The main types of relationships are:

  • One-to-One
  • One-to-Many
  • Many-to-Many

18. One-to-One Relationship

In a one-to-one relationship, one record in one table is associated with one record in another table.

Example

One student can have one student profile.

students
student_id
name

student_profiles
profile_id
student_id

19. One-to-Many Relationship

In a one-to-many relationship, one record in one table can be related to many records in another table.

For example, one course can have many students.

courses
course_id
course_name

students
student_id
name
course_id

20. Many-to-Many Relationship

In a many-to-many relationship, many records in one table can be related to many records in another table.

For example, one student can enroll in multiple courses and one course can have multiple students.

A third table called an enrollment or junction table is commonly used.

students
student_id
name

courses
course_id
course_name

enrollments
student_id
course_id

21. Creating Courses Table

CREATE TABLE courses(
course_id INT PRIMARY KEY AUTO_INCREMENT,
course_name VARCHAR(100) NOT NULL,
duration VARCHAR(50),
level VARCHAR(50)
);

22. Creating Students Table

CREATE TABLE students(
student_id INT PRIMARY KEY AUTO_INCREMENT,
name VARCHAR(100) NOT NULL,
email VARCHAR(100) UNIQUE NOT NULL
);

23. Creating Enrollments Table

CREATE TABLE enrollments(
enrollment_id INT PRIMARY KEY AUTO_INCREMENT,
student_id INT,
course_id INT,
enrollment_date DATE,
FOREIGN KEY(student_id)
REFERENCES students(student_id),
FOREIGN KEY(course_id)
REFERENCES courses(course_id)
);

28. Constraints in Your Academy Project

Constraints are useful when designing your Online Tech Learning Academy database.

  • Student ID can be a PRIMARY KEY.
  • Email can be UNIQUE.
  • Student name can be NOT NULL.
  • Course ID can be a PRIMARY KEY.
  • Enrollment student_id can be a FOREIGN KEY.
  • Enrollment course_id can be a FOREIGN KEY.
  • Student ID can use AUTO_INCREMENT.

29. Complete Example

CREATE DATABASE tech_learning_academy;

USE tech_learning_academy;

CREATE TABLE courses(
course_id INT PRIMARY KEY AUTO_INCREMENT,
course_name VARCHAR(100) NOT NULL,
duration VARCHAR(50),
level VARCHAR(50)
);

CREATE TABLE students(
student_id INT PRIMARY KEY AUTO_INCREMENT,
name VARCHAR(100) NOT NULL,
email VARCHAR(100) UNIQUE NOT NULL
);

CREATE TABLE enrollments(
enrollment_id INT PRIMARY KEY AUTO_INCREMENT,
student_id INT,
course_id INT,
enrollment_date DATE,
FOREIGN KEY(student_id)
REFERENCES students(student_id),
FOREIGN KEY(course_id)
REFERENCES courses(course_id)
);

30. Important Points to Remember

  1. Constraints are rules applied to database columns.
  2. PRIMARY KEY uniquely identifies each record.
  3. PRIMARY KEY cannot contain NULL values.
  4. FOREIGN KEY connects two related tables.
  5. NOT NULL prevents NULL values.
  6. UNIQUE prevents duplicate values.
  7. DEFAULT provides a default value.
  8. CHECK restricts values according to a condition.
  9. AUTO_INCREMENT automatically generates numeric IDs.
  10. A table can have a primary key and multiple foreign keys.
  11. One-to-one means one record is related to one record.
  12. One-to-many means one record can be related to many records.
  13. Many-to-many relationships usually require a junction table.
  14. Foreign keys help maintain relationships between tables.
  15. Proper database relationships reduce duplicate and inconsistent data.
